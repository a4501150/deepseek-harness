# Agent 笔记：经提供方所辖分拆文档实现专用模型设置文件

Status: implemented

[English](2026-09-07-dedicated-model-settings-document.md) | 中文

## 问题

被移植的提供方设置词汇表把模型配置放在独立文件里，与通用设置分离。本 harness 里每个 namespace 分节都共用一份 `settings.yaml`，于是 web Models 页面与模型选择器写入的那些分节——路由 profile、已保存的默认选择、purpose 路由——与无关 namespace 挤在同一份人类编辑的文档中。整理模型设置的用户编辑（也可能改坏）的是整份文档，而部署方没有任何办法让模型相关分节拥有自己的文件归属、同时 seam 仍看到一份文档。

## 决策

`dsh-settings-file` 新增 `documents` 配置：按路径与所辖 namespace 声明的分拆文档。被路由的 namespace 恰好只有一个文件归属。`persist` 把每个分节路由到它的拥有文档；`load` 读取每份文档，`compose` 把各解析树合并成 seam 的那一份原始文档，因此所有消费方看到的 `SettingsProvider` 约定不变。只在启动时运行的 `migrateGhosts` 把写在拥有文档之外的被路由分节迁入拥有文档并丢弃陈旧副本，让按单文档布局写下的安装收敛到位；此后外部编辑留下的幽灵只在合成时被滤除并告警，不写回。`resolveSpec` 拒绝一切会让分节归属含糊的配置：一个 namespace 两个拥有者、分拆文档指名主文档、分拆路径重复、空路径或空 namespace 条目。base bundle 把 `agent-default-model`、`model-routing`、`llm-deepseek` 与 `llm-pi-ai` 路由到 `settings.yaml` 旁边的 `model-settings.yaml`。

## 考虑过的替代方案

- **逐 namespace 一份文档，或按约定划分的布局。** 被否决：源词汇表没有要求文件数量成倍增长，而分拆是部署方的声明——提供方声明机制，挂载处点名分节。
- **只滤除幽灵、不做启动迁移。** 被否决：按旧单文档布局写入的分节会永远从错误的文件读出，且任何写入都会在会话中途搬动它；启动时迁移让既有安装一次性收敛——在首次发布之前，并留下一条点名去向的日志。
- **在设置服务内部做多文档合并。** 被否决：文件布局是文件提供方的职责；一个懂得文档分拆的服务会把本提供方的存储模型泄漏给每个提供方。

## 后果

- 既有安装在本次变更后的首次启动会把模型相关分节移入 `model-settings.yaml`（每个分节一条 info 日志）；前后的读写看到的值完全相同，因为 seam 文档无论如何都是合并后的。
- watcher 监听每一份已配置文档，写入在这一条操作链与各自文件写锁上串行，因此对一份文档的写入仍会在渲染前并入对其他任何文档的外部编辑。
- 某个分拆文档声称拥有另一个分拆文档已拥有的 namespace 时，加载即报错并点名两个文件名，而不是靠巧合解析。
